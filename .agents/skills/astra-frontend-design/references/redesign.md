# Redesign an existing interface

Use this reference when modernizing, restyling, or restructuring an existing visible product.

## Classify the mandate

Infer the redesign mode from the request:

- Preserve: improve craft while retaining the brand, information architecture, and familiar workflows.
- Evolve: retain product identity and behavior while materially improving hierarchy, composition, and interaction.
- Overhaul: establish a new visual language while preserving agreed content and functional contracts.

Ask one focused question only if the mode is genuinely unclear and different answers would lead to incompatible work.

## Audit the current truth

Inspect the running interface and the code. Capture representative screenshots before editing when browser tooling is available. Record the facts that affect decisions:

- brand colors, type, logo treatment, geometry, and signature visual elements;
- route structure, navigation labels, content order, and primary user flows;
- shared components, tokens, responsive behavior, and state patterns;
- analytics hooks, stable selectors, form names, accessibility behavior, SEO metadata, and legal text;
- elements worth preserving and the specific defects worth retiring.

Do not erase a coherent system simply because it differs from this skill's examples.

## Preserve functional contracts

Unless the user asks otherwise, keep routes, navigation meaning, form fields, content facts, legal copy, tracking hooks, keyboard behavior, and important selectors stable. Preserve good accessibility and performance characteristics. Reuse brand assets rather than silently replacing them.

## Apply the highest-leverage changes

Start with hierarchy, typography, spacing, layout rhythm, and responsive composition. Then recalibrate color, geometry, controls, and motion. Replace whole sections only when the existing structure blocks the intended workflow or visual direction.

Avoid a half-redesign where the hero follows a new system but later sections retain incompatible spacing, radii, colors, or type. Update shared tokens and primitives when that produces consistent change with less risk.

## Compare and verify

Capture the same viewports and states before and after. Compare task clarity, hierarchy, alignment, readability, content fit, brand recognition, and interaction behavior. Fix regressions before polishing details. Report meaningful preserved constraints and any intentional behavior change in the handoff.
